# Open questions, market risk and competitor context

## Direct competitive references
- Glance: dynamic widget UI layout ("UI on Demand"), MCP and data integrations. Claims must be compared against hands-on tests.
- Agent HUD: multi-agent status and mobile actions.
- Nomo, Kilo Code and CodeIsland: mobile coding-agent monitoring / approvals or desktop-presence routing.
- Apple: WidgetKit, Live Activities / Dynamic Island, Smart Stacks, App Intents, platform rules.
- AI assistants: ChatGPT, Claude, Gemini and Siri are **integrations or platform constraints**, not necessarily direct substitutes for an independent interaction layer.

## Fundamental unresolved questions
1. Is externally supplied **dynamic UI + reliable bidirectional choice response** in a single widget meaningfully better than existing products?
2. Are agents proactively willing/able to publish a UI without requiring the user to type "send to hub" each time? Exact capability depends on runtime integration.
3. Can we suppress mobile interruptions when the desktop is active, without invasive sensing?
4. Is the future ecosystem multi-agent/multi-provider, or do a few closed agents absorb most personal tasks?
5. Is any consumer willing to pay more than the free agent hub for attention management, and for what measurable benefit?
6. Does the product offer value with only 1–2 connected agents?
7. Can existing SDK/protocols (MCP, A2UI, AG-UI) reduce adapter work without assuming access to closed sessions?
8. What data permissions are needed for context-aware prioritization, and can the product stay privacy-preserving?

## Validation strategy
- Technical POC first: native widget interaction, layout change, refresh latency on device.
- Only then compare with Glance and agent monitoring alternatives.
- Then real power-user testing: task completion, non-actionable interruptions, decision turnaround, reliability and paid trials.
- Avoid overclaiming differentiation, business viability, refresh immediacy or available APIs.
